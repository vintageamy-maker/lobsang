# 設計原則與踩過的坑

← [[00-專案首頁]]

前半段是從 Base 帶過來的規則（來源是 SmartCare 實際出過的事，程式裡相關的地方都有 ⚠ 註解說明原因）；後半段是 Lobsang 自己踩到的坑。

## 資料與種子

- **種子資料可以重跑，但只新增、不改舊的**：客戶在畫面上改過的選單、角色、權限，重啟時不可以被蓋回去
- **角色用代碼認，不用名稱認**（`RoleCodes`）：用名稱的話，客戶一改名，重啟就會再長出一個權限全滿的舊名角色
- **授權只給一次**（`GrantOnceAsync`＋`seed_markers`）：客戶拿掉的權限，重啟不會長回來
- **正式站不種示範帳號**：示範帳號的密碼寫死在程式裡，出現在正式站就等於留了後門
- **本機不可連正式庫**：有正式庫之後要設定 `Safety:ProductionDatabase`，非正式環境連到它會拒絕啟動
- **刪資料前先找來源**：會自動重建的東西，只刪資料沒有用，要連來源一起關掉

## 權限與範圍

- **「能做什麼」和「看得到誰」是兩件事**：權限碼管能力，`DataScopeService` 管範圍（自己／單位／全部）
- **不要為了一個小功能開一個大權限**：需要時開一個小的權限碼
- **敏感檔案不可沿用一般分類**：`record.read` 通常全員都有，而且列表會回傳檔名，檔名本身就可能是個資
- **下載一律經過 API、每次留稽核**，不發簽章網址（外流後無法撤銷，也查不到誰看過）
- **LINE 綁定不等於可以用**：每次 LINE 操作都重新檢查帳號是否啟用，不然 LINE 會變成繞過離職控管的後門
- **LINE 不做簽核**：LINE 的短期權杖只能用白名單內的路由（`LineSessionPolicy`）

## 簽核

- **送簽當下存快照**：之後改流程、改組織，不影響已經在跑的單
- **停用帳號前先擋**：待簽單、單位主管、代理設定、指名關卡都處理完才能停用（不然單子會卡在離職的人身上）
- **單位不真的刪**：用過的單位只能停用；停用前要先把人和資料移走

## 驗證與版控

- **編譯過不等於畫面對**：一律用 Chrome 實際點過
- **前端型別檢查用 `npx tsc -b`**：這個專案結構下，`tsc --noEmit` 會檢查 0 個檔案還回報成功
- **驗證工具本身會失效**：查到「0 筆」時，先用一有一無的對照證明工具真的有在查
- **不用 `git add -A`**：只加指定的檔案；客戶提供的資料夾一出現就先加進 `.gitignore`
- **帳密不進版控**：`appsettings.Development.json`、`.env` 都被忽略；`Lobsang.csproj` 也擋住 Development 設定被打包進 publish

## Lobsang 自己踩到的坑（2026-11-07 建立時）

- **快速登入清單要寫成「JSON 字串」**：`appsettings.Development.json` 的 `DemoAccounts` 如果寫成 JSON 陣列，`AuthController` 用 `config["DemoAccounts"]` 會讀到空值，登入頁的快速登入就不會出現，而且不會報錯。要寫成 `"DemoAccounts": "[{...}]"`。
- **API 埠號要跟 Vite 的轉發對齊**：Base 的 `launchSettings.json` 寫 5173，跟 Vite 後台撞同一個埠，而 Vite 的 `/api` 轉發到 5080。Lobsang 已經把 API 改成 5080。
- **Base 的機構預設存 GCS**：本機沒有 GCS 憑證，上傳會失敗（Base 刻意讓它失敗，不會偷偷改存本機）。Lobsang 只在本機跑，所以種子改成 Local；上開發站時要改回來（見 [[03-環境與部署]]）。
- **Windows 用 `openssl rand` 產生的金鑰結尾帶 `\r`**：塞進 JSON 會讓 `dotnet ef` 報錯，產生時要接 `| tr -d '\r\n'`（AC 踩過，這次照做沒出事）。
- **npm 11 預設不執行套件的安裝腳本**：`npm ci` 時 esbuild 會跳警告。實測 Vite 照常可以用，不用處理。
- **查書全部在伺服器查**（2026-11-07 決定）：原本的單機版有一半來源在瀏覽器查。搬到伺服器後，Google 金鑰不會外流，公開頁可以統一限流和快取，國圖也不必再開 PowerShell 小伺服器。缺點是要等最慢的來源（國圖約 5～15 秒）回來才一起顯示
- **公開 API 一定要限流**：查書會打國圖、UPCitemdb，被大量查詢時對方可能擋掉我們的伺服器 IP，結果所有人都不能用
- **國圖書號中心沒有 API**：是模擬網頁操作（拿 csrftoken → 送表單 → 抓 HTML）。國圖改版面就會查不到，屆時對照網頁原始碼改 `BookLookupService.FromNcl` 的 regex
- **誠品線上不能當自動資料來源，只能放連結**（2026-11-07）：整站（含搜尋 API `athena.eslite.com`）有 Cloudflare 機器人防護，程式查詢一律回 403。繞過機器人防護不做，所以只在「其他網站」放搜尋連結。博客來等有防護的商業網站也是同樣處理
- **歐美書幾乎全靠 Google Books**：沒有金鑰就共用全世界的匿名額度，幾乎一直 429。Open Library 是志工維護，新書常常還沒收錄。查不到歐美書時先看 Google 的狀態是不是「額度用完」（申請金鑰見 [[03-環境與部署]]）
- **這台電腦記憶體只有 8 GB**：Chrome 一多，Claude Code 會在背景把 API、Vite 關掉（通知說三個都關了，實際上只有 API 被關，Vite 還在）。症狀是前端畫面正常、但查詢回 500（Vite 轉發連不到 API）。處理：關掉多餘的 Chrome 分頁，再把 API 重開
- **專案資料夾在另一個 git repo 裡面**：`C:\Han` 本身是一個 repo，Lobsang 自己另外 `git init`，並在 `C:\Han\.gitignore` 加了 `Lobsang/`，外層 repo 才不會把它收進去。
- **相機掃條碼**（2026-11-07）：`BarcodeScanner.tsx` 在 `React/src` 和 `ReactAdmin/src/components` 各一份，**改一邊要同步另一邊**。用 barcode-detector 的 ponyfill（iPhone Safari 沒有內建 BarcodeDetector）；辨識用的 wasm（約 950 KB）從自己網站的 assets 載入，第一次按掃描才下載，不走套件預設的 jsDelivr。相機只能在 https 或 localhost 開，http 網頁不會出現「掃描」按鈕。日本書下面那條 191／192 開頭的分類碼會被忽略，要掃上面 978 那條。後台「連續掃描」是同一個元件加 `continuous`：同一條碼停在鏡頭前不會重送，離開超過 3 秒再掃才算一次（同一輪重複的由書單頁再擋）
- **書單匯出 Excel**（2026-11-07）：CSV 是純文字，**存不了字型、顏色**，要指定字型（微軟正黑體）或標題列樣式只能匯出 .xlsx。用 exceljs 4.4.0（約 940 KB），寫成 `import('exceljs')` 按匯出才載入，不拖慢書單頁。條碼欄在 Excel 存成文字（numFmt `@`），CSV 才需要 `="..."` 那招
- **誠品線上（瀏覽器端查詢）**（2026-11-07）：`eslite.ts` 兩個前端各一份，**改一邊要同步另一邊**。⚠ 誠品 v1 商品 API 的 `final_price`＝**定價**、`retail_price`＝售價，跟搜尋 API（`mprice`＝定價、`final_price`＝售價）相反。⚠ 搜尋是關鍵字比對，一定要比對回來的 `isbn`／`ean` 等於查的 ISBN。⚠ 第二層分類常是促銷標籤（「📌文學館79折起」）要濾掉。⚠ 誠品偶爾要十幾秒才回，設 15 秒逾時；任何錯誤都只標在查詢來源，不能讓查書失敗。這是誠品前端自用、沒文件的 API，哪天壞了先看這裡
- **售價（salePrice）**（2026-11-07）：誠品 v1 商品 API 的 `retail_price`。⚠ 新增書籍欄位時，**後端 `Services/BookLookup/BookInfo.cs` 也要加**：後台存書時是後端把前端送來的 info 反序列化成 C# `BookInfo` 再存 `data_json`，C# 沒有的欄位會被**悄悄丟掉**（不會報錯）。所以這次要連 API 一起部署
- **用 SQL 查不在 EF 模型裡的表**（2026-11-07，`openbd_books`）：用 `db.Database.SqlQuery<T>(...)` 時**欄位不要取別名**。專案的 EF 設定會把 C# 屬性名轉成蛇形（`CoverUrl` → `cover_url`）再去對欄位，取了 `AS CoverUrl` 反而會找不到（錯誤：`Unknown column ... cover_url`）
