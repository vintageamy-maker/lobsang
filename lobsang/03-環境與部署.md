| 東西 | 位置 |

### 啟動（每次開機後）

```bash
# 1. 資料庫（Docker Desktop 要先開著；容器設定成 Docker 啟動時自動起來）
cd deploy/local && docker compose up -d
# 2. API → http://localhost:5080
cd API/Lobsang && dotnet run --launch-profile http
# 3. 後台 → http://localhost:5173/admin/
cd ReactAdmin && npm run dev
# 4. 主站（公開查書頁）→ http://localhost:5174/
cd React && npm run dev -- --port 5174 --strictPort
```

> ⚠ 本機的主站和後台是不同埠號，所以主站頁尾的「後台」連結（`/admin/`）在本機打不開，要自己開 5173。上了開發站之後兩個在同一個網址，就正常了。

### Google Books API 金鑰（查書用，2026-11-07 已設定在本機）

沒有金鑰時，伺服器查 Google Books 是跟全世界沒金鑰的人共用免費額度，幾乎一直回 429「額度用完」。
⇒ 歐美書只剩 Open Library 一個來源，新書常常查不到（例：2026-11-07 查 `9780241833162`，Penguin UK 的書，Google 額度用完、Open Library 三種查法都沒有）。

| 項目 | 說明 |
|---|---|
| 費用 | **免費**。Books API 沒有付費方案，超過額度只會當天查不到，不會收費 |
| 額度 | 每個專案每天約 1,000 次；查到的結果伺服器會快取 6 小時，同一本書重複查不重算 |
| 信用卡 | 一般不用綁。Google Cloud 第一次登入推薦的「免費試用」是給其他付費服務用的，可以跳過 |
| 放哪裡 | 本機：`appsettings.Development.json` 的 `BookLookup:GoogleApiKey`（不入版控）；開發站：VM `.env` → compose 環境變數 `BookLookup__GoogleApiKey` |

申請步驟（要用業主自己的 Google 帳號）：
1. 開 https://console.cloud.google.com/ 登入
2. 上方建立專案（例如 `lobsang`）
3. 「API 和服務」→「程式庫」→ 搜尋 **Books API** →「啟用」
4. 「API 和服務」→「憑證」→「建立憑證」→「API 金鑰」，複製 `AIza…` 開頭的金鑰
5. 建議在金鑰設定裡「限制金鑰」只能用 Books API（外流也只能拿來查書）
6. 填進設定後重開 API（重開也會清掉舊的查詢快取）

> ⚠ 費用與額度是 2026-11-07 依 Google 的方案說明整理，申請時以畫面為準；看到任何要收費的字樣先停下來確認。


### 只更新前端（2026-11-07 起實際用的做法）

只改畫面時不用動 API、不用重啟容器，nginx 直接讀新檔案：

1. 本機：改了哪個就 build 哪個（公開頁 `React`、後台 `ReactAdmin`，`npm run build`），把 `dist` **裡面的內容**打包成 `web-YYYYMMDD-HHMMSS.tgz`／`admin-YYYYMMDD-HHMMSS.tgz`
2. 開 IAP 通道（見上面「怎麼連進主機」），`scp` 到 VM 的 `/tmp/`，解到暫存資料夾
3. 備份：`sudo cp -a dist dist.bak.時間`（後台是 `admin-dist`）
4. 換檔：先清空**資料夾裡面**再複製進去，然後 `chmod -R a+rX`
5. 檢查 `index.html` 引用的 assets 檔案都在；在 Chrome 開 f66.io 實際點過
6. 每種備份只留最近 3 份；做完把 IAP 通道關掉

- ⚠ **不要整個換掉 `dist`／`admin-dist` 資料夾**（例如 `mv` 新資料夾過去）：它們是 bind mount 掛進 nginx 容器的，換掉資料夾容器還是看舊的那個，要整個重啟才會變
- ⚠ 在 VM 刪檔一律寫**完整路徑**（`sudo rm -rf /home/cheng/lobsang/dist/*`），不要寫 `$d/*` 這種變數：變數是空的就變成刪根目錄，Claude Code 的安全檢查也會直接擋掉
- 要退回上一版：把 `dist.bak.時間` 的內容照第 4 步複製回 `dist`
- 網路中斷（IAP 通道回 `getaddrinfo failed`、ssh exit 255）時：先重開通道，**確認主機上沒有做到一半**（有沒有多出這次時間的 `.bak`、`/tmp` 有沒有上傳的檔），再整個重做
