## 三個核心機制

- **簽核**：表單 → 流程（可依條件分流）→ 關卡（角色／第 N 層主管／指定人；可以會簽，也可以任一位簽）。送簽當下會存成「快照」，之後改流程設定，不影響已經在跑的單。代理人代簽時會記下「代誰簽」。
- **資料可見範圍**（`DataScopeService`）：自己／單位／全部。「能做什麼」看權限碼，「看得到誰」看組織樹和單位主管，兩件事分開管。
- **權限**：權限碼掛在角色上，登入時放進 JWT；把 `users.token_version` 加 1，那個人的舊登入就會立刻失效。

查完會附「其他網站」連結（點了在使用者自己的瀏覽器開；**公開頁的詳細內容彈窗不顯示**，只有查不到時的畫面和後台查書看得到）：台灣書＝博客來、**誠品線上**、國圖、Google Books；日本書＝Amazon.co.jp、版元ドットコム、博客來、誠品線上、Google Books；其他＝Amazon.com、Google Books、Open Library、博客來、誠品線上。

**保護措施**：
- 公開 API 以 IP 限流：查外部資料庫 **每分鐘 20 次**、搜尋書單每分鐘 60 次，超過回 429。後台的查詢不限流
- 查到的結果在記憶體快取 6 小時、查不到的快取 10 分鐘（重開 API 就清掉）
- 書單的「備註」只有後台看得到，公開 API 不回傳
- Google Books 金鑰放伺服器設定 `BookLookup:GoogleApiKey`，使用者看不到

### 採購候選的兩個階段：採購清單 → 採購審核（2026-11-08）

業主 2026-11-08：採購候選分兩個階段——第一階段是「查詢後加入的清單」（採購清單），第二階段是「採購審核清單」，**主管審核後再加入商品**。

| 項目 | 內容 |
|---|---|
| 畫面 | 選單「書籍 → 採購候選」`/admin/books`，頁面內兩個分頁：**採購清單**（`Books.tsx` 的 `PurchaseList`）、**採購審核**（`PurchaseOrders.tsx`）。網址 `?tab=review` 可直接開審核分頁 |
| 已在商品清單 | 2026-11-10：採購清單表格裡已在商品清單的書，名稱前有橘色「已在商品清單」標籤（滑過去看店內碼、庫存、上下架；後端列表多回傳 `product`）。查書時若條碼已在商品清單，**跳出提示視窗**（名稱、店內碼、庫存、上／下架），查書結果上方也有橘色標示；勾「查到後自動加入」或用「連續掃描」時**不加入採購清單**（連續掃描標「已在商品清單」），要補貨可自己按「加入採購清單」。後端 `GET /api/admin/books/lookup` 多回傳 `product` |
| 送審 | 採購清單勾選（換頁也記得）→「送審」→ 每本填**採購數量**、可寫說明 → 建一張**採購單**（單號 `PO-yyyyMMdd-流水號`，台灣日期）；送出的書**從採購清單移到採購單**（業主決定），明細存當時的完整資料（快照），**每次送審的內容都有紀錄** |
| 審核 | 採購單可**逐本核准／退回**（可複選、全選待審）；退回要寫原因，**退回的書放回採購清單**（備註註明「PO-… 退回：原因」；清單已有同條碼就不重複放）。核准／退回要有 **`purchase.approve`（採購審核）**權限，業主決定**先只給系統管理員**（系統管理員本來就全通，沒有另外勾給角色） |
| 上架 | 核准的書由員工按「上架」：填**店內碼（必填、不能跟現有商品重複）**、商品名稱（預設書名）、中／子分類、售價、庫存（預設＝採購數量）、上架開關 → 建成商品（查書資料一起帶過去）；明細狀態變「已上架」並記下商品 id |
| 狀態 | 明細：待審 pending → 核准 approved（待上架）／退回 rejected → 已上架 listed。採購單本身不存狀態，列表顯示各狀態本數 |
| 資料表 | `purchase_orders`（單號、送審人、送審時間、說明）、`purchase_order_items`（條碼、書名、作者、出版社、備註、`data_json` 快照、數量、狀態、退回原因、核准／退回人與時間、商品 id）—— migration `AddPurchaseOrders` |
| API | `POST/GET /api/admin/purchase-orders`、`GET /api/admin/purchase-orders/{id}`、`POST /api/admin/purchase-orders/{id}/decide`（purchase.approve）、`POST /api/admin/purchase-orders/items/{itemId}/list` —— `AdminPurchaseOrdersController`（其餘用 book.manage） |
| 業主決定 | 審核單位＝一張採購單（多本）；簡單版審核（一關、看權限，不接簽核引擎）；核准後由員工上架時填商品欄位；送審要填採購數量（不填進價） |
| 之後可能做 | 接內建簽核引擎（多關、依金額分流、LINE 通知）、進價／預算、採購單作廢 |
